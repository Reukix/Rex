## 概要

v0.9.7 build 970 确立“Rex 外壳、Chromium 语义”的产品边界。用户看到的导航、标签、扩展列表和 `rex://extensions` 管理页均由 Rex 的 SwiftUI/AppKit 界面承载；网页渲染、导航生命周期、扩展执行、权限与配置状态继续由 Chromium 实现并作为唯一事实来源。

`chrome://extensions` 不再作为可见页面嵌入 Rex。它只保留在不可见、受控的 Chromium 上下文中，用于调用原生扩展管理 API。旧的 `chrome://extensions` 地址会在应用边界迁移到 `rex://extensions`，不会向用户暴露 Chrome 标签栏、地址栏或扩展管理 WebUI。

## 主要变化

### Rex 扩展管理界面

- `rex://extensions` 使用 Rex 自有页面显示扩展发现、已安装列表、安装、启停、移除、选项入口和详情。
- `rex://extensions?id=<runtime-id>` 打开对应扩展详情；无效或重复 ID 不会被当作有效详情路由。
- 地址栏直接输入合法 `chrome://extensions` 旧地址时会迁移到对应 `rex://extensions` 列表或详情；其他 `chrome://` WebUI 仍被拒绝。
- 管理页属于 Rex 应用状态，不向 Chromium 页面发送可见导航，也不依赖 Chromium 原生窗口的坐标、焦点或窗口层级。
- 扩展自身的 `default_popup`、options 和其他包内资源仍由 Chromium 在 `chrome-extension://` 安全源中执行，对外地址继续显示为 `rex-extension://`。

### Chromium 权威配置

- 网站访问提供“点击扩展时”“指定网站”“所有网站”三种 Chromium 原生运行范围。
- “指定网站”支持为全站型扩展添加或移除授权网站，也支持对有限 host 声明逐项授权或撤销；Rex 调用 Chromium 原生 `addHostPermission` / `removeHostPermission`，不维护平行权限表。
- 支持读取与更新“允许运行用户脚本”和“允许访问文件网址”；只有 Chromium 报告该能力可用时才显示对应开关。
- 详情页同时展示 Chromium 返回的实际启用状态、可修改性、已请求网站及其授权状态。
- 每次修改都通过隐藏的受控管理上下文调用 `chrome.developerPrivate.updateExtensionConfiguration`，随后立即读取 `getExtensionInfo` 的结果。界面以读回值为准，不用 Rex 本地字段推断写入成功。
- Chromium 返回无效数据、API 不可用或写入失败时，Rex 保留错误并提供重试；写入失败后会再次读取 Chromium 权威状态，不把目标值伪装成已生效状态。

### 浏览器状态职责

- Chromium 继续拥有已提交 URL、标题、加载状态、进度、前进后退、失败和导航代次；Rex 负责地址输入、命令意图和可见呈现。
- 主网页 surface 不再把 Chromium 回报的 `tab.url` 重新提交给运行时。显式地址输入仍走 Rex 命令入口，链接、重定向和站内导航则保持 Chromium 单向驱动，不再产生同地址二次 reload 或持续刷新。
- 标签已经建立 Chromium 页面身份但 NSView 尚未挂载时，显式导航会进入原生待处理队列，并在 browser 创建后执行。
- 每个允许的新主框架请求在 `OnBeforeBrowse` 分配导航代次，redirect 继续沿用原请求代次；即使 Chromium 的聚合 loading 在替换未完成页面时一直为 true，新地址仍能提交并结束 Rex pending 状态。
- 主框架每次非重定向导航开始时建立新代次，服务器重定向保持在该代次；上一页面仍在加载时再次提交地址，也能接受 Chromium 的最终地址和 `isLoading=false`。
- Chromium 继续执行 service worker、content script、DNR、消息、storage 和扩展页面。Rex 不解析扩展脚本或规则来模拟这些行为。
- 扩展的安装、更新、启停、明确移除和冷启动恢复继续通过串行运行时事务与 Chromium profile 对账。

### 扩展更新与会话恢复

- 已停用扩展重新启用时，Chromium 依次执行 `management.setEnabled(true)` 与 `developerPrivate.reload`。这会重新读取磁盘上的受管包，覆盖禁用期间发生且没有提升 manifest 版本号的 JS/CSS 更新，也不依赖 Rex 进程内的临时差异标记。
- 运行时事务要求原生操作成功、最终 Chromium 注册状态验证通过，并确认受管包仍匹配事务开始时的指纹快照。任何操作错误或事务期间的二次换盘都会失败并进入恢复流程，同版本更新不会再因注册表字段没有变化而误报成功。
- 扩展冷启动屏障仍会让恢复网页的 CEF 实例暂时加载 `about:blank`；每个标签的占位标记会保留到首个真实地址提交，因此屏障释放后的延迟回调也不会覆盖 Rex 导航状态或 SQLite 中的恢复 URL。

### CEF 正常退出

- 退出准备先取消普通会话保存的 350ms debounce，等待恢复任务和既有写队列，再把全部活动标准窗口的最新快照写入 SQLite；隐私窗口跳过，单窗口失败不会阻断其他窗口，5 秒超时后继续关闭并记录日志。
- 退出请求先关闭全部 Chromium browser；最后一个 browser 关闭后停止 `NSApplication` 主循环，由显式 SwiftUI 入口在 `NSApplication.run` 返回后排空 CEF 外部消息泵并调用 `CefShutdown()`。
- 内部扩展控制 DevTools pipe 在排空关闭任务前断开，固定 fd 3/4 在 `CefShutdown()` 返回后释放。CEF 不再从 `applicationWillTerminate` 的 `terminate:` 调用栈内关闭。

- Swift Testing `162/162`、Release Notes Validator（28 个功能 ID）、CEF bridge arm64 Release、完整 Xcode Release、MV3 verifier 语法与自测通过。

- 网站访问三态、用户脚本和文件网址开关已覆盖成功读取、成功写入和 Chromium 返回值不同于请求值的权威读回回归；详情实测显示 Tampermonkey 的 Chromium 状态为已启用、所有网站、允许用户脚本与文件网址。失败、超时、跨窗口与真实脚本注入仍保留在后续矩阵中。
- 具体网站输入规范化、原生 grant/revoke 更新模型、写入失败后的二次权威读回，以及退出前多标准窗口即时保存、恢复中等待、隐私窗口跳过和单窗口失败隔离均有聚焦回归。
- 隔离 MV3 实测已确认安装运行、content script、service worker、DNR、双向消息和停用语义；停用期间同版本更新后再启用、连续两次正常冷启动、storage sentinel 与无重复 onboarding 尚未获得最终包的完整证据，因此本版不宣称 MV3 冷启动矩阵完整通过。
- C++ 策略回归覆盖可见 `chrome:` 导航拦截、屏障释放后的启动占位地址隔离、停用后重新启用的强制 reload，以及“原生操作 + 注册状态验证 + 指纹快照稳定”三条件提交。
- 最终 ZIP 的 `0.9.7 / 970`、全部 11 个 Mach-O 的 arm64、ad-hoc deep/strict codesign、解压、载荷一致性、清单和 SHA-256 验证通过；隔离退出烟测确认主进程与全部 Helper 在 TERM 后 10 秒内退出。

## 已知边界

- build 970 是 ad-hoc 本地 Beta 基线，不是 Developer ID 正式分发候选。Developer ID 同团队签名、Hardened Runtime、公证、装订、Gatekeeper、应用更新和失败回退仍未完成。
- iCloud Passwords 的扩展包和权限可以加载，但 Apple native host 当前不可用。Rex 缺少 Apple 要求的 manifest 注册、正式签名身份和 managed entitlement；本版本不会复制或重签 Apple helper，也不会伪装受支持浏览器身份。
- Rex 小型面板不是 Chromium 原生 action popup。完整 `activeTab`、无静态 popup 的 `action.onClicked`、动态 `action.setPopup` 和部分 `chrome.tabs.create` 后续 ID 语义仍不承诺支持。
- 静态 popup 只接收来源 tab ID，并通过 Chromium `tabs.get` 获得按扩展权限裁剪的 Tab；Rex 不提供 URL/标题旁路。未声明 `tabs` 或匹配 host permission 时，扩展不得读取这些敏感字段。
- 网站访问、用户脚本与文件网址的配置链路和已覆盖的 MV3 子集通过，不代表任意用户脚本、所有 Chrome Web Store 扩展或全部 Chrome API 均兼容；Tampermonkey 最小用户脚本注入仍需独立实测。
- Chrome Web Store 扩展尚不自动更新，仍需使用相同商店 ID 手动重新安装新版包。
