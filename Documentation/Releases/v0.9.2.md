## 通用 Chromium 扩展运行时

v0.9.2 把扩展能力从可信获取和包管理推进到已验证的 Chromium 扩展运行子集，同时保持 Rex 自己的产品界面：

1. Rex 继续提供扩展发现、安装状态、已安装列表、小型面板入口和扩展管理界面。列表行可整行进入扩展交互，小型面板直接加载清单声明的静态 `default_popup` 资源，options 页面使用 `rex-extension://<runtime-id>/<包内路径>` 打开。
2. Chrome Web Store CRX2/CRX3 继续执行来源限制、扩展身份/签名验证和安全解包；本地 Manifest V2/V3 文件夹继续复制到受管目录。
3. 商店包在每次读取时重新验证 manifest 公钥，并要求公钥推导的 Chromium runtime ID 与验签 store ID 相同。缺少公钥或身份不一致的旧包必须重新安装。
4. 当前启动前启用的受管包由 Chromium 扩展运行时直接加载。已验证的 service worker、content script、runtime messaging、storage、DNR 与 options 页面来自真实安装包，Rex 不解析规则后模拟扩展行为，也没有 AdGuard 专用执行路径。
5. Rex 只承载扩展交互的容器和导航；静态 `default_popup`、options 等资源直接来自已安装扩展包，内部仍在 `chrome-extension://` 安全源中执行，对外统一显示为 `rex-extension://`，而不是 Rex 针对单个扩展重做的前端。
6. 小型面板不触发 Chromium 原生 action popup，也不因此获得 `activeTab` 或 `chrome.tabs` 当前窗口语义。未声明静态 popup 而依赖 `action.onClicked` 的按钮，以及运行时 `action.setPopup` 动态变更，当前不支持。

扩展加载集合是进程启动快照。安装、启用、停用和移除会更新下次启动配置，需要重新启动 Rex 才会改变 Chromium 中的实际运行状态。仍在当前进程运行的扩展不会被原位删除；移除请求会在下次启动前完成清理。

## 当前验证

本地 MV3 黑盒探针已经确认：

- background service worker 可启动并处理事件。
- content script 可注入页面。
- runtime messaging 可在扩展上下文之间往返。
- `chrome.storage.local` 可读写。
- declarativeNetRequest 规则由 Chromium 执行并真实阻断请求。
- options 页面加载真实扩展内容。
- 静态 `default_popup` 可从扩展包直接加载到 Rex 小型面板。

最终 `Dist` Release 包的通用 MV3 黑盒探针会依次等待 service worker、content script/DNR、options 和 popup 就绪，连续两次均为 `8/8` 通过。以上能力和静态 `default_popup` 均已纳入同一探针；该结果只验证 fixture 覆盖的真实包内能力，不代表 Chromium 原生 action popup、所有 Chrome Web Store 扩展或全部 Chrome API 均兼容。Swift Testing `128/128`、完整 CEF bridge 的 Xcode arm64 Debug/Release 构建和 Release Validator 均通过。

真实 UI 冒烟使用相同的通用扩展路径：非广告 fixture 从扩展列表整行进入小型面板，扩展自身 popup 自动调整为 `280×113`，显示 `Ready` 并与 service worker 完成消息交互；AdGuard popup 自动调整为 `320×600`，分段交互有效，没有扩展专用代码。普通 Rex 起始页、侧栏、导航栏和分屏回归确认没有裁剪、负偏移或 Chrome 窗口覆盖。未托管的 Chrome extension popup/auxiliary window 会把普通网页目标交给 Rex 后关闭，不保留额外 Chrome 窗口。

## 已知限制

- 安装、启用、停用和移除均需重新启动 Rex 生效，不支持热修改当前 Chromium 进程的扩展集合。
- stock CEF 150 的 Alloy 嵌入路径没有 Chromium 活动窗口/标签模型，Rex 小型面板不提供 `activeTab` 授权，也不保证 `tabs.query({active:true,currentWindow:true})` 等 `chrome.tabs` 当前窗口语义。
- 未声明静态 `default_popup` 而依赖 `action.onClicked` 的扩展按钮，以及通过 `action.setPopup` 在运行时动态变更 popup 的流程，当前不支持。
- Chrome Web Store 自动更新尚未完成；当前只能通过受管安装流程重新获取包。
- Developer ID 签名、公证与应用自动更新尚未完成。

## 发布验收

- 主 App 与五个 CEF Helper 均为 `0.9.2 / 920`，仅包含 arm64。
- deep codesign、ZIP 解压完整性、SHA-256 清单和 Release Validator 均通过。
- 隔离 profile 重复启动通过：首个 Dist Release 实例运行时，第二个相同 profile 实例输出 `Existing process handled launch; exiting relaunch process.` 并以 exit code 0 正常退出。
- Rex 源码和主可执行文件不包含 `SystemPasswordsCoordinator` 或 `AuthenticationServices` 依赖，不提供系统密码调用功能。打包门槛同时拒绝 Rex 主 executable 链接 `AuthenticationServices` 或 App 包含任何 `.systemextension`，`PACKAGE-INFO.txt` 记录 `rex_password_integration=absent`。上游 Chromium Embedded Framework 自身仍链接该系统 framework，因此不把这一结论扩大到整个应用 bundle。
