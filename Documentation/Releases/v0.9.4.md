# Rex v0.9.4

发布日期：2026-07-28<br>
构建号：940<br>
通道：Beta<br>
平台：macOS 14+ / Apple Silicon arm64

## 本版重点

v0.9.4 将受管 Chromium 扩展从“下次启动生效”推进为完整热生命周期。安装、启用、停用、手动更新和移除会在当前 Rex 进程中与 Chromium 对账；冷启动恢复的网页则等待扩展就绪后才发出首次导航，不再要求用户重启应用或手动刷新页面。

## 热安装、启停、更新与移除

- Rex 在 `CefInitialize` 前预留 fd 3/4 专用传输，Chromium 以 `--remote-debugging-pipe` 启动；browser-target `Extensions.getExtensions`、`Extensions.loadUnpacked` 和 `Extensions.uninstall` 只通过该本地通道调用。
- 该控制面不绑定 loopback 或其他 TCP 监听地址，普通网页 target 也不能取得 browser CDP 会话。
- 每次变更分配串行 generation；只有 Chromium 返回的实际启用受管路径与预期集合一致后，操作才视为完成。ID、路径、版本和启用状态会保留在运行时观测结果中。
- 安装、启用、停用、手动更新和移除成功后，活跃普通窗口中已加载的 HTTP(S) 页面各立即重载一次；休眠或冻结页面在恢复时重载一次，隐私窗口不运行扩展也不参与热重载。`about:`、`rex-extension:` 等内部页面同样排除。
- 同路径更新在换盘前原子写入 `runtime-replacements.json`；Chromium 确认后才提交并清理旧包。若进程在 ack 前退出，下次启动会恢复上一版本与目录记录。
- 重新导入已在 Rex 受管目录内编辑的本地扩展时会显式要求 Chromium unload/load，因此仅覆写既有 JS/CSS 也不会被目录与 manifest 的快速指纹漏掉。
- 可信获取边界不变：Chrome Web Store 包仍需通过来源、CRX 身份/签名与安全解包校验，本地 Manifest V2/V3 包仍复制到 Rex 受管目录。

## 冷启动首次文档

恢复的 HTTP(S) browser 先保持 `about:blank` 并保存 pending URL。Rex 不把 `CefInitialize` 返回或隐藏窗口创建完成当作扩展就绪；只有当前 extension-ready generation 完成对账后才统一放行目标 URL。预期集合为空时也会先清理 Chromium profile 中可能残留的受管 unpacked 扩展，不直接绕过屏障。

这个屏障保证内容脚本与 DNR 从恢复页面的首次文档开始生效，而不是依赖随后刷新。通用 MV3 发布探针也必须直接检查这份首次文档，不允许通过刷新或重复 `Page.navigate` 掩盖竞态。

## 路由修复

- 修复 `chrome.tabs.create` 转交目标时，临时 Chrome browser 与 Rex 正式标签对同一 URL 各发出一次主文档请求的问题。
- 隐藏的扩展 `about:blank` 上下文不再被 MV3 探针误识别为 Rex 网页 target。
- 扩展小型面板与包内页面继续沿用 v0.9.3 的通用容器和 `rex-extension://` 应用边界，不增加单扩展专用路径。

## 性能

- 受管扩展启动校验从每包两次完整文件树扫描降为一次；启停只更新内存运行状态，不重复扫描包目录。
- 单次 manifest 解析只读取一次 `_locales/.../messages.json`，名称和描述复用同一本地化字典。
- Chrome Web Store 下载中的进度约每 80 毫秒合并发布一次，完成、取消和失败终态立即送达。
- 探针删除已定位目标后的重复导航，冷启动和 DNR 检查复用真实首次文档。
- 多个普通窗口合并为一次进程级首次扩展对账；窗口关闭会取消恢复、导航、休眠和引擎事件任务，并销毁该窗口全部 Chromium 页面，避免隐藏 renderer、媒体、网络和扩展注入继续运行。
- 会话即时保存与延迟保存统一串行；恢复过程中快速关窗不会用占位标签覆盖旧快照，手动关闭副窗口会在待处理保存结束后删除记录，整体退出仍保留全部当前窗口。

## 已知边界

- Rex 小型面板不是 Chromium 原生 action popup；无静态 popup 的 `action.onClicked` 与运行时 `action.setPopup` 尚未支持。
- 当前探针覆盖的能力不代表所有 Chrome Web Store 扩展或全部 Chrome API 均兼容。
- Chrome Web Store 扩展尚不自动检查更新，可使用相同官方链接或扩展 ID 手动重新安装。
- Chromium profile 中先前持久化的旧 extension worker 可能在启动清理 generation 前短暂初始化；恢复的 HTTP(S) 首次导航仍会保持在屏障后。完全阻止 worker 初始化需要更早的 profile 事务恢复。
- 同路径更新已具备换盘 journal 与崩溃回滚，但仍不是“先等待 Chromium unload ack、再替换目录”的完整两阶段切换；极窄的换盘到卸载窗口由下次启动回滚覆盖。
- 当前本地包使用 ad-hoc 签名；Developer ID、公证与应用自动更新仍未完成。
