# Rex v0.9.3

发布日期：2026-07-28<br>
构建号：930<br>
通道：Beta<br>
平台：macOS 14+ / Apple Silicon arm64

## 本版重点

v0.9.3 是扩展交互的稳定性更新。它修复扩展小型面板首次打开时暴露 CEF 白色占位首帧、随后二次调整尺寸造成的卡顿，并补齐扩展自身打开包内设置页时从 `chrome-extension://` 到 Rex 标签页的安全路由。

## 改进

- 小型面板在 Chromium 返回首个有效内容尺寸后再显示，最终尺寸、位置和阴影在同一帧应用。
- 同一窗口会话会复用扩展上一次确认的面板尺寸，减少重复打开时的布局跳变。
- 加载期间收到的自动尺寸在扩展主文档完成时立即回传，不再额外等待固定 300 ms。
- 静态 `default_popup` 仍由真实扩展包直接运行，没有加入扩展专用 UI 或行为。

## 修复

- 修复首次打开扩展时短暂出现白色区块的问题。
- 修复扩展面板加载完成后延迟调整宽高造成的卡顿。
- 修复扩展设置按钮通过 `chrome.tabs.create(chrome-extension://…)` 创建包内页面时无法进入 Rex 的问题。
- 为扩展后台建立始终隐藏的 Chrome Views 窗口上下文，修复 CEF 因不存在 current window 而在协议路由前拒绝 `chrome.tabs.create` 的问题。
- 将未托管 Chrome 标签的转交时机延后到主框架开始导航，避免创建回调中 URL 尚为空时提前关闭。
- 修复 popup 先执行 `window.close()` 时来源标签被清空、随后创建的设置页无法正确归属的问题。

## URL 边界

Chromium 内部继续使用 `chrome-extension://`，以保留扩展源、权限、API 和生命周期语义。进入 Rex 应用状态前，经过验证的包内地址统一转换为 `rex-extension://<runtime-id>/<包内路径>`。HTTP、HTTPS 和 About 弹窗继续由 Rex 接管；带凭据、无效 runtime ID 或无法通过资源路径验证的地址不会进入 Rex 标签模型。

## 验证

- Swift Testing：`128/128` 通过。
- CEF Objective-C++ bridge：arm64 增量编译通过。
- AdGuard 实机冒烟：从扩展小型面板点击设置后进入 `rex-extension://…/pages/options.html`，窗口列表未出现额外 Chrome UI。
- Release Validator、完整 Xcode Debug/Release 构建、最终 ZIP、签名、校验和与运行时冒烟结果以 `Dist` 中本版打包记录为准。

## 已知边界

- 安装、启用、停用和移除扩展仍需重新启动 Rex 后生效。
- 小型面板仍不是 Chromium 原生 action popup；无静态 popup 的 `action.onClicked` 与运行时 `action.setPopup` 尚未支持。
- 兼容性取决于扩展使用的 Chrome API 与当前 CEF/Chromium 宿主能力，不代表所有 Chrome Web Store 扩展均兼容。
- 当前本地包使用 ad-hoc 签名；Developer ID、公证与自动更新仍未完成。
