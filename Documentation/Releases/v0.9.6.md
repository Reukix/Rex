## 概要

v0.9.6 保持 `rex://extensions` 到 Chromium 原生 WebUI 的直接映射，并修复完整 Chromium 窗口在 Rex 内容区内的绘制/点击坐标偏移。普通非隐私 HTTP(S) 页面改由 Chrome runtime 承载，使扩展获得真实 tab/window/frame identity；冷启动不再把持久扩展作为命令行扩展重复安装。build 962 同时把导航加载状态收敛到 Chromium 单一事实来源，修复重定向后页面已完成但 Rex 导航栏仍持续刷新的问题。

## 主要变化

### Chromium 功能与 Rex 界面边界

- Rex 保留当前导航栏、地址栏和加载动画设计；网页导航、加载、进度、前进后退与刷新/停止状态全部来自 Chromium，Rex 不再为提交地址提前合成 loading 状态。
- CEF 主框架在每次加载开始时分配单调递增的导航代次，并在地址、加载、进度、标题和失败回调中携带该代次。Swift 事件入口在主线程保持 CEF 原始顺序，旧代次回调不会覆盖新导航。
- 待处理导航仍会阻止上一页回调覆盖用户刚提交的地址，但允许同一 Chromium 导航代次内的重定向、HSTS、登录跳转和 URL 规范化提交最终 URL。最终 `isLoading=false` 因而可以恢复刷新按钮并停止进度动画。
- 会话恢复不再复用上次运行持久化的 loading、进度、前进后退或导航代次；只保留 URL、标题等恢复目标，等待当前 Chromium 实例重新报告实时状态。

### 原生扩展管理页

- `rex://extensions` 直接映射 `chrome://extensions/`，详情路径与查询参数继续由 Chromium 原生页面处理；Rex 没有实现替代管理页。
- Chrome runtime 按 Rex 宿主的真实初始尺寸创建完整 `CefWindow`，并用填充布局管理内部 browser view。实现不再把 browser view 从 Chromium 窗口拆出后重挂载到 Rex；而是把完整 Chromium 窗口作为 Rex 内容窗口的无边框原生子窗口，按内容区屏幕坐标同步位置和大小。
- Chromium 子窗口保持 key 状态，让原生 responder 接收网页键盘输入；Rex 内容窗口只恢复 main-window 身份。应用菜单、sheet 和工具栏扩展面板因此仍以 Rex 主窗口为层级基准，而不会从 Chromium 子窗口夺走键盘事件。

### 当前标签与双向消息

- 普通非隐私 HTTP(S) 页面使用 Chrome runtime，内容脚本与 service worker 的 sender 因而具有 Chromium 真实 tab、window、frame 和 document identity。
- 静态 popup 的 `{active:true,currentWindow:true}` 与 `{active:true,lastFocusedWindow:true}` 查询使用 CEF 明确定义为扩展 `tabId` 的 `CefBrowser::GetIdentifier()` 精确匹配 Chromium 实际标签。相同 URL/标题不会被误选，来源标签已关闭时返回空数组。
- MV3 探针要求 currentWindow/lastFocusedWindow 返回同一来源标签 identity，并把其 tab ID/window ID 与同一文档的内容脚本 sender 直接比较，同时记录 frame ID 和 document ID。
- service worker 使用 `chrome.tabs.sendMessage` 向指定来源 frame 回传并获得内容脚本确认，补齐双向消息覆盖。
- popup 触发 background worker 执行 `{active:true,lastFocusedWindow:true}` 后，探针会把结果与 popup 及内容脚本 sender 的真实 `tab.id/windowId` 直接比较，覆盖 Tampermonkey 实际使用的查询路径。

### 冷启动生命周期

- Browser process 仍会删除外部传入的 `--load-extension`，也不再使用 CDP `Extensions.loadUnpacked` 创建 Chromium 会在下次启动清理的临时记录。路径真正缺失时，Rex 通过隐藏的 Chromium 原生扩展管理 WebUI 调用 `chrome.developerPrivate.loadUnpacked`，生成可由 profile 跨启动恢复的原生 unpacked 记录。
- 同 ID 更新使用 `chrome.developerPrivate.reload`，启停使用 `chrome.management.setEnabled`；只有明确移除才卸载，避免重装造成 `chrome.storage`、权限与安装生命周期重置。
- 这修复了 Tampermonkey 每次 Rex 启动都再次收到 `runtime.onInstalled`、并重复打开安装成功页面的问题。旧 CDP 记录升级后会迁移一次，之后不再重复安装。
- MV3 回归连续执行两次启用态重启，每次要求 `runtime.onStartup` 与 worker 启动报告，同时明确拒绝 `runtime.onInstalled` 和 onboarding 页面请求，并要求持久 storage UUID 保持不变。

### iCloud Passwords 状态

- 官方扩展 ID `pejdijmoenmkgeppbflobdenhhabjlaj` 在扩展包已加载时仍保留 `.ready` 运行状态；Apple 原生连接限制是纯计算的兼容性状态，不写入扩展持久化数据。
- 已安装列表显示橙色 Apple 原生连接限制，工具栏列表显示“Apple 原生连接受限”，action 面板也给出同一限制说明，不再把“扩展包已加载”误报为 iCloud Passwords 完整可用。

## 已知边界

- iCloud Passwords 的扩展包和权限可以加载，但 Apple 原生连接当前不可用。系统 manifest 位于 `/System/Library/Templates/Data/Library/Google/Chrome/NativeMessagingHosts/com.apple.passwordmanager.json`，没有注册给 Rex；QA 日志对应记录 `Can't find manifest for native messaging host com.apple.passwordmanager`。Apple helper 的 Parent Launch Constraints 还要求获批的 `com.apple.developer.web-browser.public-key-credential` managed entitlement，或名单内的 Bundle ID + Team ID。当前 ad-hoc `com.rex.browser` 没有 Developer ID 和该 entitlement，也不在 helper 名单中；仅复制 manifest 无法启动 helper。本版本不会复制、重签 Apple helper 或伪装受支持浏览器身份。
- Rex 小型面板仍不是 Chromium 原生 action popup；保留真实 tab identity 不等于授予完整 `activeTab`。无静态 popup 的 `action.onClicked` 与动态 `action.setPopup` 尚未支持。
- `chrome.tabs.create` 只保证目标 URL 被转交并创建可见 Rex 标签；创建请求对应的 Chromium 临时 WebContents 随后关闭，因此回调中的临时 `tab.id` 不保证可继续用于 `tabs.get/update/sendMessage`。语义正确的支持需要接管原 WebContents 和完整 CefClient 生命周期，本版不做 ID 模拟。
- 已验证的 service worker、content script、双向消息、storage、静态 DNR、options、静态 popup 和 tab identity 子集不能外推为全部 Chrome Web Store 扩展或全部 Chrome API 均兼容。
- 当前包仍为 ad-hoc 签名、关闭 Hardened Runtime 且未公证，只适合本地 Beta 验证。
